- [x] 1.2 建立前端與後端的本機開發整合設定：定義 Vue 開發伺服器、API base URL、開發 proxy/CORS 與啟動說明，使瀏覽器只呼叫 EatThis API；驗證從 Vue 開發環境送出的請求會到本機 API，且 production bundle 不依賴硬編碼的 Google endpoint。
- [x] 2.1 完成 `### Decision: Secret handling and request protection` 的設定邊界：提供不含真實值的 server-side Google 設定範例、local secret/production secret-manager 命名、development/production key restriction 說明，並更新 `.gitignore` 排除本機秘密檔；驗證 repository 追蹤檔、前端 source 與範例設定均沒有 Google API key 格式的真實值。
- [x] 3.1 定義 `### Decision: Normalized provider-neutral place contract` 的 API/domain 型別與 provider interface：以 latitude、longitude、radiusMeters 表示查詢，以 name、address、latitude、longitude、distanceMeters、navigationUrl、provider 表示候選地點，讓未來 OSM adapter 能替換 Google 而不改變前端 selection contract；驗證介面與 DTO 的欄位契約有自動化測試，且不暴露 raw provider payload。
- [x] 3.2 實作 `### Requirement: Expose a bounded nearby-food pick endpoint` 與 `### Decision: On-demand geolocation and bounded radius` 的輸入驗證：建立 `POST /api/nearby-food/pick`，限制 latitude 為 -90..90、longitude 為 -180..180、radiusMeters 為 100..5000，省略半徑時使用 3000；驗證合法請求可通過，邊界外座標、低於下限與大於 5000 的半徑均回傳穩定的 HTTP 400 error code。
- [x] 3.3 實作 `### Requirement: Preserve a provider-neutral replacement contract`：讓 application service 只依賴 provider-neutral query/provider abstraction，並將候選清理規則（缺少名稱、無效座標、無法使用的 navigationUrl）集中在 provider boundary 後；驗證以替代 provider double 回傳同一 normalized shape 時，主要 selection flow 不需要引用 Google-specific 型別。
- [x] 4.1 實作 `### Decision: Backend-owned Google Places provider` 與 `### Requirement: Query Google Places through an adapter`：由 ASP.NET Core backend 以 server-side configuration 讀取 Google key，建立固定的 Nearby Search request、固定 food-related place types 與最小 field mask，並將 Google Maps URL 映射為 `navigationUrl`；驗證 provider double 能檢查只建立一次受限請求、正確 mapping，且 live Google request 不會出現在測試。
- [x] 4.2 完成 `### Requirement: Keep the provider credential server-side` 與 `### Requirement: Restrict the backend proxy behavior`：只接受位置與受控半徑，不接受 arbitrary upstream URL、field mask、provider type 或 Google key，且 response 僅含選定地點的公開欄位；驗證前端 request payload、public response、compiled bundle 與瀏覽器 network payload 都沒有 Google credential 或 raw upstream response。
- [x] 5.1 依據 `### Decision: Random selection occurs after provider normalization` 與 `### Requirement: Select exactly one nearby food place` 實作 selection service：在候選清理後，使用可注入且可測試的 random source 從單次 provider response 均勻選出一個候選，禁止重複提交造成多次同一操作的 provider call；驗證多候選、單候選與空候選案例，成功 response 永遠只有一個 candidate，且空集合回傳 no-results。
- [x] 5.2 實作 `### Requirement: Return stable failure responses` 與 `### Failure contract`：將 invalid input、no normalized candidates、backend rate limit、Google authentication/quota/upstream failure 分別映射為穩定 HTTP status 與 client-readable error code，不把 raw upstream message 或 credential 寫入 response；驗證各錯誤分支的 status、error code、retry guidance 與敏感資料排除。
- [x] 6.1 依據 `### Decision: Tests use provider doubles and browser capability mocks` 建立 API automated tests：涵蓋 `### Request contract`、輸入邊界、provider mapping、navigation URL、random selection、no-result、upstream failure、rate limit 與 public response 不含 key；驗證測試使用 provider double/configuration fake，不需要 live Google credential、live Google request 或外部網路。
- [x] 6.2 為 API endpoint 加入 server-side request protection：設定以 client identity 或 request source 為界的 rate limit、取消/timeout 與 upstream failure logging policy，避免記錄 Google key 或 raw provider response；驗證超過限制會回傳 429 與可操作的 retry guidance，正常請求仍只執行一次 provider call。
